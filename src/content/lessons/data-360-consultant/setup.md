## この範囲で問われること

- Data 360 のプロビジョニングと組織の考え方
- 権限セットとアクセス管理
- データスペース
- 設定の移行（パッケージ・データキット）と運用の監視

## 1. 組織と環境

- Data 360 は Salesforce の組織（ホーム組織）上で動作する。他の Salesforce 組織も**コネクター**でつなげる。
- Sandbox でも Data 360 を使って検証できる（Data 360 対応の Sandbox）。

## 2. 権限

- 標準の権限セット（**Data Cloud Admin**、**Data Cloud Architect**、**Data Cloud Marketing Manager / Specialist**、**Data Cloud User** など）で役割ごとにアクセスを付与する。
- **最小権限**: セグメントを作る人、データを取り込む人、見るだけの人で分ける。
- 機密データには**データガバナンスのポリシー**（属性ごとのアクセス制御）を検討する。

## 3. データスペース

- **データスペース**で、データ・メタデータ・処理を**論理的に分離**する（例: ブランドごと、地域ごと、事業部ごと）。
- データスペースごとにアクセス権を付与でき、別ブランドのデータを見せない運用ができる。
- 既定のデータスペースは「default」。

## 4. 設定の移行と運用

- **データキット**と**パッケージ**で、データストリーム・データモデル・ID 解決などの設定を別の組織に移行する。
- 運用の監視: データストリームの更新状況とエラー、ID 解決の処理結果、セグメントの公開状況、**消費（クレジット）の使用量**。
- **データの更新スケジュール**を、業務に必要な鮮度とコストのバランスで決める。
