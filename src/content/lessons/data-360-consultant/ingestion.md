## この範囲で問われること

- コネクターとデータストリーム
- 取り込み方式（バッチ・ストリーミング・ゼロコピー）
- データレイクオブジェクト（DLO）とデータモデルオブジェクト（DMO）
- カテゴリ（プロファイル・エンゲージメント・その他）とマッピング

## 1. 主なデータソース

| ソース | 方法 |
|---|---|
| Salesforce の CRM 組織 | **Salesforce CRM コネクター**（取引先・取引先責任者・リードなど。バンドルで簡単に） |
| Marketing Cloud Engagement | Marketing Cloud コネクター（メール・SMS のエンゲージメント） |
| Web サイト・モバイルアプリ | **Web / Mobile SDK**（行動データをストリーミング） |
| クラウドストレージ | Amazon S3、Google Cloud Storage、Azure などからファイルを取り込み |
| DWH | **ゼロコピー**（Snowflake・Databricks・BigQuery など）でコピーせず参照 |
| その他のシステム | **Ingestion API**（ストリーミング・バルク）、MuleSoft、各種コネクター |

## 2. データストリームの作成

1. ソースとオブジェクトを選ぶ
2. **カテゴリ**を選ぶ
   - **プロファイル**: 人や会社の属性（顧客マスターなど）
   - **エンゲージメント**: 時刻を持つ行動・取引（購入、メール開封、Web 閲覧）。**イベント日時の項目が必須**
   - **その他**: 上記以外（商品マスター、店舗など）
3. **主キー**を決める（重複を防ぐ）
4. 必要なら**数式項目**で値を整える（取り込み時の簡単な変換）
5. 更新方式（**更新・置換**、スケジュール）を決める

## 3. DLO と DMO

- 取り込んだデータはまず**データレイクオブジェクト（DLO）**に保存される（ソースの形のまま）。
- それを**データモデルオブジェクト（DMO）**にマッピングして、共通の形（**Customer 360 データモデル**）にそろえる。
  - 例: 個人（Individual）、連絡先（メール・電話・住所）、販売注文、エンゲージメントなど。
- 標準 DMO で足りなければ**カスタム DMO**。
- ID 解決には、**個人**と**連絡先ポイント**、**パーティ識別**の DMO へのマッピングが重要。
