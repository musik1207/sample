## この範囲で問われること

- データの調和（ハーモナイゼーション）
- ID 解決ルールセット（一致ルール・調整ルール）
- 統合個人プロファイルと統合リンク
- ID 解決の結果の確認と調整

## 1. 調和

- 各ソースの項目の意味をそろえ、**同じ DMO の同じ項目**にマッピングする（例: EC の「mail」と CRM の「Email」を、連絡先メールの「メールアドレス」に）。
- 形式の違い（電話番号の書式、国コード）は**数式項目**や**正規化**でそろえる。

## 2. ID 解決

**ID 解決ルールセット**で、どのデータを同じ人とみなすかを決めます。

### 一致ルール

| 方法 | 例 |
|---|---|
| **完全一致** | メールアドレスが同じ |
| **正規化した一致** | 大文字小文字や空白を無視して一致 |
| **ファジー一致** | 名前の表記ゆれ（ファーストネームなど）を許容 |
| **パーティ識別（外部 ID）** | 会員番号・ロイヤルティ ID が同じ |

- 複数の条件を組み合わせる（例: 「姓 ＋ メールアドレス（正規化）」**または**「会員番号」）。
- 条件が**緩すぎる**と別人が統合され（過剰マッチ）、**厳しすぎる**と同じ人がまとまらない。

### 調整ルール

- 統合プロファイルの各項目に、**どのソースの値を採用するか**を決める。
  - **最終更新日時**（最新の値）、**最も頻繁な値**、**ソースの優先順位**。

## 3. 結果

- **統合個人（Unified Individual）**: まとめられたプロファイル。
- **統合リンク**: 統合プロファイルと元のレコードの対応。
- ID 解決の**処理サマリー**で、元のプロファイル数と統合後の数（統合率）を確認し、ルールを調整する。
- **統合連絡先ポイント**（統合後のメール・電話の一覧）も作られる。
