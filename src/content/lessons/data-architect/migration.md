## この範囲で問われること

- 移行の計画（範囲・順番・リハーサル）
- 移行の手法とツール
- 性能の最適化
- 検証と切り替え

## 1. 計画

1. **範囲**: 何を、何年分、どの品質で移すか。不要なデータは移さない。
2. **マッピング**: 旧システムの項目 → Salesforce の項目、選択リストの値、所有者の対応。
3. **順番**: 親 → 子（ユーザー → 取引先 → 取引先責任者 → 商談 → 商談商品 → ケース → 活動・ファイル）。
4. **リハーサル**: Full Sandbox などで本番と同じ量で試し、時間を測る。
5. **切り替え計画**: 旧システムの停止、差分の移行、ロールバックの方法。

## 2. 手法

- **外部 ID**で旧システムのキーを持ち、**upsert**で親子を紐づける。
- **監査項目（作成日・作成者など）**を旧システムの値で入れたい場合は、「監査項目の設定を有効化」して作成時に設定する。
- **ツール**: データローダー（Bulk API）、ETL ツール、MuleSoft など。
- 添付ファイルは**ContentVersion**として移行する。

## 3. 性能の最適化

- Bulk API の**並列モード**で速く。ロック競合（同じ親の子を別々のバッチで同時に処理）が起きたら、**親でソート**するか直列モードに。
- **自動化（Flow・トリガー）・入力規則を一時的に無効化**、**共有計算の延期**。
- 必要な**ユーザーとロール**を先に作り、所有者を正しく設定する。
- 大量の移行は**業務時間外**に。

## 4. 検証と切り替え

- **件数・合計値の照合**、サンプルレコードの業務担当者による確認。
- 移行エラーのログ（エラーファイル）を確認し、修正して再投入。
- 切り替え後のハイパーケアと、旧システムを参照できる期間を決める。
