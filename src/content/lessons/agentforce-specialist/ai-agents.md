## この範囲で問われること

- エージェントの種類（顧客向け・従業員向け）と使い分け
- トピック・指示・アクションの設計
- Atlas 推論エンジンの動き
- 変数・フィルター・決定的な制御

## 1. エージェントの種類

| 種類 | 対象 | 例 |
|---|---|---|
| **サービスエージェント** | 顧客 | 注文確認・返品受付・FAQ（メッセージングなど） |
| **従業員向けエージェント（Agentforce アシスタント）** | 社内ユーザー | レコードの要約、メールの下書き、データの検索 |
| **営業向けエージェント** | 見込み客・営業担当 | リードへの初期対応、営業コーチ |
| **その他のテンプレート** | 業界・業務ごと | 予約、フィールドサービスなど |

- 顧客向けは**エージェントユーザー**の権限で動き、従業員向けは**利用者本人の権限**で動く。

## 2. 構成要素

- **トピック**: 仕事の単位。**分類の説明**（どんな依頼を扱うか）と**範囲**（何をするか・しないか）で、依頼がどのトピックに振り分けられるかが決まる。
- **指示（Instructions）**: トピック内での振る舞い。具体的に、1 つの指示に 1 つのルール。「必ず〜」「〜の前に〜」。
- **アクション**: 実際の処理。**Flow・Apex（呼び出し可能メソッド）・プロンプトテンプレート・標準アクション（レコードの照会、ナレッジの回答など）・API**。
  - アクションの**説明**と**入力・出力の説明**が、推論エンジンの選択に使われる。わかりやすく書く。
  - 入力が必要なものは「ユーザーからの入力を必須」「確認を求める」などを設定。

## 3. 推論の仕組み

- **Atlas 推論エンジン**が、依頼を理解 → トピックを選ぶ → 指示に従ってアクションを選ぶ → 結果を評価 → 必要なら次のアクション → 回答、を繰り返す。
- 生成 AI なので**確率的**。毎回同じ順番を保証したい処理は**決定的に**作る。

## 4. 決定的な制御

- **変数**: 会話の中で値を保持する（例: 本人確認済みかどうか）。
- **フィルター（条件）**: 変数の値でトピックやアクションを使えるかを制御する（例: 本人確認が済むまで返金アクションを使えない）。
- 確定的な処理は **Flow / Apex** に任せる。
- 重要な操作の前に**ユーザーへの確認**を挟む。
