## この範囲で問われること

- Einstein Trust Layer の機能
- エージェントの権限設計
- 監査と可観測性（ログ・追跡・分析）
- ガードレールと責任ある AI

## 1. Einstein Trust Layer

| 機能 | 内容 |
|---|---|
| **安全なデータ取得** | ユーザーの権限に基づいてデータを取得 |
| **動的グラウンディング** | 信頼できるデータで回答の根拠を与える |
| **データマスキング** | 個人情報などを LLM に送る前に伏せる |
| **プロンプトの防御** | システムポリシーで不適切な動作を抑える |
| **ゼロデータリテンション** | 外部の LLM プロバイダーにデータを保持・学習させない |
| **有害性の検出** | 出力の有害性をスコア化 |
| **監査証跡** | プロンプトと応答、スコアを記録 |

## 2. 権限

- 顧客向けエージェントは**エージェントユーザー**で動く → **最小権限**の権限セット。
- 従業員向けは**利用者本人**の権限で動く → 見られないデータは使えない。
- アクションで使う **Flow・Apex** の実行コンテキスト（システムモードかユーザーモードか）にも注意。
- 機能を使える人を**権限セット**で制御する（プロンプトテンプレートの実行、エージェントの管理など）。

## 3. 可観測性

- **監査とフィードバックのデータ**（Data 360 に保存）で、プロンプト・応答・有害性スコア・ユーザーのフィードバックを分析。
- **エージェントの分析・セッションの追跡**で、どのトピック・アクションが使われ、どこで失敗したかを確認。
- 定期的にレビューし、問題のパターンを改善につなげる。

## 4. ガードレール

- トピックの**範囲**で、扱わない依頼を明確にする。
- **人への引き継ぎ**を設計する（機密・高リスクの依頼）。
- 出力を人が確認する運用（ヒューマン・イン・ザ・ループ）。
- AI を使っていることを利用者に**明示**する。
