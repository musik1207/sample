## この範囲で問われること

- レポート・ダッシュボード・リストビューの共有
- ファイル・Chatter・ナレッジ・活動の可視性
- Apex・Visualforce・LWC での共有の扱い（with sharing など）
- 項目の暗号化・マスキングなど

## 1. レポートとダッシュボード

- **フォルダ**で共有（参照者・編集者・管理者）。
- レポートの**結果は実行ユーザーの権限**で表示される（見えないレコードは出ない）。
- ダッシュボードの**表示ユーザー**を「特定のユーザー」にすると、閲覧者はそのユーザーの権限のデータを見る → **機密データの露出に注意**。
- **動的ダッシュボード**は閲覧者の権限で表示。

## 2. ファイル・Chatter・ナレッジ・活動

- **ファイル**: 共有されたレコード・ユーザー・グループ・ライブラリを通じて見える。レコードに添付したファイルはレコードへのアクセスで見られる。
- **Chatter**: レコードのフィードはレコードへのアクセスに従う。グループは公開／非公開。
- **ナレッジ**: **データカテゴリの表示範囲**と公開チャネルで制御。
- **活動（ToDo・行動）**: 関連先レコードへのアクセスに従う（親による制御）。プライベートな行動もある。

## 3. コードと共有

| キーワード | 動き |
|---|---|
| `with sharing` | 実行ユーザーの共有ルールを適用 |
| `without sharing` | 共有ルールを無視（システムモード） |
| `inherited sharing` | 呼び出し元の設定を引き継ぐ |

- 共有キーワードは**レコードアクセス**だけ。**オブジェクト権限と項目レベルセキュリティ**は別途チェックする: `WITH USER_MODE` / `WITH SECURITY_ENFORCED`、`Security.stripInaccessible`、`Schema.DescribeFieldResult` など。
- Flow も「システムコンテキスト（共有あり／なし）」と「ユーザーコンテキスト」を選べる。
- **LWC の Lightning Data Service** はユーザーの権限と共有を自動で尊重する。

## 4. その他

- **Shield Platform Encryption**: 保存時の暗号化（見え方は権限次第）。
- **クラシック暗号化項目**: 「暗号化された項目の参照」権限がないとマスクされる。
- **ユーザーの可視性**: ユーザーの OWD、外部ユーザーから見える内部ユーザーの範囲。
- **ポータル・サイトのユーザー情報**: プロファイルの表示設定で個人情報を隠す。
