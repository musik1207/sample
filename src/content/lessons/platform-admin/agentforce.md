## この範囲で問われること

- Agentforce のユースケースと、AI を使うべき場面・使うべきでない場面
- エージェントの構成要素（トピック・指示・アクション）
- エージェントのセキュリティと権限、アクセスのトラブルシューティング
- Agentforce Builder での指示・プロンプトの保守とテスト

## 1. AI を使うべき場面

- **向いている**: 自然な言葉での問い合わせ対応、要約、下書き作成、情報検索、定型的だが言い回しが毎回違う作業。
- **向いていない**: 結果が常に同じでなければならない処理（金額計算、確定的な条件分岐）。これは **Flow や入力規則**のほうが確実。
- 判断の基準は「**決まったルールで必ず同じ結果にしたいか**」。そうなら AI ではなくルールベースの自動化。

## 2. エージェントの構成要素

| 要素 | 役割 |
|---|---|
| **トピック** | エージェントが扱う仕事の単位（例: 注文状況の確認）。**分類の説明**と**範囲**で、どの依頼をこのトピックで扱うかを決める |
| **指示（Instructions）** | トピック内での振る舞いのルール（自然言語） |
| **アクション** | 実際に行う処理。**Flow・Apex・プロンプトテンプレート**などを呼び出す |
| **Atlas 推論エンジン** | ユーザーの依頼を理解し、トピックとアクションを選んで実行する |

- **プロンプトビルダー**: 差し込み項目でレコードのデータを入れた**プロンプトテンプレート**を作る（例: 取引先の要約）。
- データで回答の根拠を与えることを**グラウンディング**と呼ぶ。

## 3. 信頼性とセキュリティ

- **Einstein Trust Layer**: データマスキング、プロンプトの防御、**ゼロデータリテンション**（外部 LLM 側にデータを保持させない）、有害性の検出、監査ログ。
- エージェントは**エージェントユーザー**（サービスエージェントの場合）や**実行中のユーザー**の権限で動く。**見えないデータは使えない**。
- エージェントがデータにアクセスできないとき確認すること
  1. エージェントユーザー／ユーザーに**必要な権限セット**が付いているか
  2. 対象オブジェクト・項目の**オブジェクト権限・項目レベルセキュリティ**
  3. レコードの**共有設定**
  4. アクションの元になる **Flow や Apex** を実行する権限
- 機密性の高い操作は**人間への引き継ぎ（エスカレーション）**を設計する。

## 4. 保守とテスト

- **Agentforce Builder** でトピック・指示・アクションを編集する。
- **会話プレビュー**で実際に話しかけ、どのトピック・アクションが選ばれたかの**推論の流れ**を確認できる。
- 期待どおりに動かないとき
  - 違うトピックが選ばれる → トピックの**分類の説明**や範囲を見直す
  - 手順を守らない → **指示**を具体的にする
  - アクションが動かない → アクションの説明・入出力・権限を確認
- **Testing Center** で多数のテストケースを一括で評価できる。
- 変更はまず **Sandbox** で試し、エージェントのバージョンを管理する。
