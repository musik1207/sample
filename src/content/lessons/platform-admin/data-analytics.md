## この範囲で問われること

- データインポートウィザードとデータローダーの使い分け
- データ品質（入力規則・重複管理）
- バックアップと Sandbox
- レポートの種類・グラフ・集計・バケット・行レベルの数式
- ダッシュボードと表示ユーザー

## 1. データの取り込み

| | データインポートウィザード | データローダー |
|---|---|---|
| 件数 | **5 万件まで** | **500 万件まで**（それ以上は他の手段） |
| 対象 | 主要な標準オブジェクト＋カスタムオブジェクト | ほぼすべてのオブジェクト |
| 操作 | 新規・更新・upsert | 新規・更新・**upsert**・**削除**・**完全削除**・**エクスポート** |
| 重複チェック | 取り込み時にできる | 外部 ID などで制御 |
| 実行 | ブラウザから | デスクトップアプリ、コマンドラインで**定期実行**可能 |

- **upsert**: 外部 ID（または Salesforce ID）で一致すれば更新、なければ新規作成。
- 取り込み時にワークフローや Flow が動くことに注意（一時的に無効化することもある）。

## 2. データ品質

- **入力規則**: 不正な値の保存を防ぐ。
- **一致ルール＋重複ルール**: 重複の警告またはブロック。
- **必須項目・選択リスト・外部 ID の一意**で、そもそも汚れにくい設計にする。
- **項目履歴管理**: 項目の変更履歴を記録（オブジェクトごとに上限あり）。

## 3. バックアップと環境

- **データエクスポートサービス**: 週次（または月次）で全データを CSV で書き出す。
- **Salesforce Backup** などの有償バックアップ製品もある。
- **ごみ箱**: 削除したレコードは 15 日間保持され、復元できる。
- **Sandbox の種類**

| 種類 | データ | 用途 |
|---|---|---|
| Developer | 設定のみ | 開発・単体テスト |
| Developer Pro | 設定のみ（容量大） | 開発・統合テスト |
| Partial Copy | 設定＋**データの一部**（テンプレートで選択） | テスト・研修 |
| Full | 設定＋**全データ** | 性能テスト・本番同等の検証 |

## 4. レポート

- **レポートタイプ**: どのオブジェクトの組み合わせを報告できるか。カスタムレポートタイプで「A と B（B があるもの／ないものも含む）」を定義できる。
- **レポート形式**

| 形式 | 特徴 |
|---|---|
| 表形式 | 一覧。ダッシュボードには行数制限付きでのみ使える |
| サマリー | 行でグループ化。**グラフが付けられる** |
| マトリックス | 行と列でグループ化 |
| 結合 | 複数のレポートタイプのブロックを並べる |

- **バケット項目**: 値を範囲やカテゴリでまとめる（例: 金額を大中小に）。項目を作らずにレポート内で分類できる。
- **集計式**: グループごとの合計に対する計算（例: 成約率）。
- **行レベルの数式**: 各行で計算する（レポートに 1 つ）。
- **レポートの購読**: 条件を満たしたら定期的にメール送信。
- **カスタムサマリー式**の `PARENTGROUPVAL`・`PREVGROUPVAL` も覚えておく。
- レポートの共有は**フォルダ**の共有（参照者・編集者・管理者）で制御する。

## 5. ダッシュボード

- コンポーネント: グラフ・ゲージ・指標・表など。**1 つのコンポーネントは 1 つの元レポート**。
- **表示ユーザー（実行ユーザー）**
  - **特定ユーザーとして表示**: 全員が同じデータを見る。
  - **ダッシュボードの閲覧者として表示（動的ダッシュボード）**: 閲覧者自身の権限で見えるデータだけを表示。
- **ダッシュボードフィルター**で表示を切り替えられる。
- ダッシュボードも**フォルダ**で共有する。
