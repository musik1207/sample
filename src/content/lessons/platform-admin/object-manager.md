## この範囲で問われること

- 標準オブジェクトとカスタムオブジェクトの使い分け
- 項目の型（数式・積み上げ集計・選択リスト連動など）
- **主従関係と参照関係**の違い
- レコードタイプ・ページレイアウト・Lightning レコードページ・動的フォーム

## 1. オブジェクトと項目

- まず**標準オブジェクトで足りないか**を考え、足りなければカスタムオブジェクト（API 名の末尾が `__c`）。
- 主な項目の型

| 型 | 使いどころ |
|---|---|
| 数式 | 他の項目から計算。**読み取り専用**で保存はされない |
| 積み上げ集計 | **主従関係の主側**で子の件数・合計・最小・最大を出す |
| 選択リスト／複数選択リスト | 値の候補を固定。**グローバル選択リスト値セット**で複数項目に使い回せる |
| 連動選択リスト | 制御項目の値によって選べる値を絞る |
| 外部 ID | 外部システムのキー。データローダーの upsert で使う |
| 自動採番 | 連番を自動で付ける |

- **入力規則**: 条件式が TRUE になると保存をエラーにする（「TRUE ＝ エラー」）。
- 項目の型を変えるとデータが失われることがある（例: テキスト → 数値）。

## 2. リレーション

| | 主従関係 | 参照関係 |
|---|---|---|
| 結びつき | 強い（子は親なしで存在できない） | 弱い（任意にできる） |
| 削除 | 親を消すと子も消える | 子は残る（設定次第） |
| 所有者・共有 | 子は**親の共有設定を継承**し、所有者項目を持たない | 子は独自の所有者・共有を持つ |
| 積み上げ集計 | **使える** | 標準では使えない |
| 上限 | 1 オブジェクトに 2 つまで | 40 まで |

- **多対多**: 2 つの主従関係を持つ**連結オブジェクト**で表現する。
- **階層関係**: ユーザーオブジェクト専用の参照（上司など）。
- 既存の参照関係を主従関係に変えるには、**全レコードの参照項目に値が入っている**必要がある。

## 3. レコードタイプとページレイアウト

- **レコードタイプ**: 業務ごとに「選択リストの値」「ページレイアウト」「ビジネスプロセス（商談のフェーズ・リードの状況など）」を切り替える。
- **ページレイアウト**: 項目・関連リスト・ボタンの配置。**プロファイル × レコードタイプ**の組み合わせで割り当てる。
- ページレイアウトで「必須」「参照のみ」にしても、それは**画面上だけ**。データローダーや API には効かない。全経路で必須にしたいなら項目自体の必須設定か入力規則を使う。

## 4. Lightning アプリケーションビルダー

- **Lightning レコードページ**: コンポーネントを配置してレコードページを作る。**アプリ・レコードタイプ・プロファイル**の組み合わせで割り当てられる。
- **コンポーネントの表示条件**: 項目の値・デバイス・権限などで表示を切り替える。
- **動的フォーム**: 項目単位でページ上に配置し、条件で表示・非表示を切り替えられる（ページレイアウトの項目セクションを置き換える）。
- **動的アクション**: ボタン（アクション）を条件で出し分ける。
- **Lightning アプリ**: タブ・ユーティリティバー・ブランドを束ねたもの。ナビゲーション形式（標準／コンソール）を選ぶ。
- アクションの種類: **オブジェクト固有アクション**（その場で関連レコードを作る等）と**グローバルアクション**（どこからでも使える）。
