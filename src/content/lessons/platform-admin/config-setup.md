## この範囲で問われること

- 会社の設定（会社情報、会計年度、営業時間、通貨、ロケール）
- ユーザーの作成・無効化・凍結とライセンスの考え方
- **オブジェクト権限・項目権限・レコードアクセス**の違いと組み合わせ
- ログインの制限（IP 範囲、ログイン時間、多要素認証）

## 1. 会社の設定

| 設定 | ポイント |
|---|---|
| 会社情報 | 組織のデフォルトのロケール・言語・タイムゾーン・通貨。ライセンスの残数もここで確認 |
| 会計年度 | **標準会計年度**（開始月だけ変更）と**カスタム会計年度**（4-4-5 など）。カスタムは一度有効にすると元に戻せない |
| 営業時間・祝日 | ケースのエスカレーションやマイルストンの時間計算に使う |
| 通貨 | 複数通貨を有効にすると無効に戻せない。**換算レート**を管理し、日付付き換算レートは商談と商談商品などで使われる |

## 2. ユーザー管理

- ユーザーは**削除できない**。退職者は**無効化**する。
- すぐに無効化できない事情（承認プロセスの承認者、カスタム階層項目の参照先など）があるときは**凍結**してログインだけ止める。
- ユーザーには必ず **1 つのプロファイル**と **1 つのユーザーライセンス**が付く。ロールは任意。
- パスワードのリセットやログインの代理（「ログインアクセスの許可」）もよく出る。

## 3. アクセス制御の全体像（最重要）

アクセスは 3 層で考えます。**上の層で許可されていないと、下の層がいくら広くても使えません。**

1. **オブジェクト権限**（参照・作成・編集・削除・すべて参照・すべて変更）… プロファイル／権限セットで付与
2. **項目レベルセキュリティ**（参照可能・参照のみ）… プロファイル／権限セットで付与
3. **レコードアクセス**（どのレコードを見られるか）… 共有の仕組みで付与

### プロファイルと権限セット

- **プロファイル**: ユーザーに 1 つだけ。ログイン時間・IP 範囲・ページレイアウト割り当てなど「基本の枠」。
- **権限セット**: 追加で何個でも付けられる。**権限は足し算だけ**で、取り上げることはできない。
- **権限セットグループ**: 権限セットを束ねて付与。**ミュート権限セット**でグループ内の一部の権限だけ打ち消せる。
- Salesforce の推奨は「プロファイルは最小限、権限は権限セットで足す」。

### レコードアクセス（共有）

| 仕組み | 役割 |
|---|---|
| **組織の共有設定（OWD）** | ベースライン。非公開／公開・参照のみ／公開・参照・更新など。**最も制限された状態**をここで決める |
| **ロール階層** | 上司は部下のレコードにアクセスできる（カスタムオブジェクトは「階層を使用したアクセス許可」で制御） |
| **共有ルール** | 所有者ベース／条件ベースで、公開グループ・ロールなどに例外的に共有を広げる |
| **チーム** | 取引先チーム・商談チーム・ケースチーム |
| **手動共有** | レコードごとに個別に共有 |
| **制限ルール** | 見える範囲を**狭める**ための仕組み（共有を広げる他の仕組みとは逆向き） |

覚え方: **OWD で一番絞る → ロール階層・共有ルール・チーム・手動共有で広げる**。

> よくあるひっかけ: 「OWD が公開・参照のみだけど編集させたい人がいる」→ 共有ルールで「参照・更新」を付与する。ただしその人のプロファイル／権限セットに**編集権限**がなければ編集できない。

## 4. ログインとセキュリティ

- **ログイン IP 範囲（プロファイル）**: 範囲外からはログインできない。
- **信頼済み IP 範囲（ネットワークアクセス）**: 範囲内なら本人確認を省略するだけで、範囲外もログイン可能。
- **ログイン時間（プロファイル）**: 時間外はログインできず、ログイン中なら切断される。
- **多要素認証（MFA）**: Salesforce は MFA を必須としている。
- **ヘルスチェック**: セキュリティ設定をベースラインと比較してスコア表示。
- **設定変更履歴**: 誰がいつ設定を変えたかを追跡（過去 180 日分）。
