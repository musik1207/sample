## この範囲で問われること

- API の使い分け（REST・SOAP・Bulk・Composite・GraphQL・Streaming）
- イベント駆動（プラットフォームイベント、変更データキャプチャ）
- 連携のセキュリティ（認証・認可・暗号化）
- エラー処理・冪等性・順序の設計

## 1. Salesforce の API

| API | 使いどころ |
|---|---|
| **REST API** | 汎用。少量のレコード操作、モバイル・Web |
| **SOAP API** | 厳密な型が必要な企業システム |
| **Bulk API 2.0** | 大量データの読み書き（非同期） |
| **Composite API** | 複数の操作を 1 回の呼び出しにまとめ、往復を減らす |
| **GraphQL API** | 必要な項目だけを柔軟に取得 |
| **Pub/Sub API** | イベントの発行・購読（gRPC、高効率） |
| **Apex REST / SOAP** | 独自のロジックを API として公開 |

## 2. イベント駆動

- **プラットフォームイベント**: 業務イベント（例: 受注確定）を発行し、外部や Flow・Apex が購読する。**疎結合**で、発行側は受け手を知らなくてよい。
- **変更データキャプチャ（CDC）**: レコードの作成・更新・削除を自動でイベントとして配信。外部のデータを Salesforce と同期させるのに向く。
- 購読側は **Replay ID** で取りこぼしたイベントを再取得できる（保持期間内）。
- **アウトバウンドメッセージ**: 宣言的に SOAP メッセージを送信。受信確認がなければ再送。

## 3. セキュリティ

- **認証**: OAuth 2.0（サーバー間連携は **JWT ベアラーフロー** や **クライアントクレデンシャルフロー**）。
- **接続アプリケーション（外部クライアントアプリケーション）**で、外部システムからの API アクセスを管理し、スコープを絞る。
- **連携ユーザー**: 専用のユーザーに**最小権限**を付与する（API のみのユーザー、権限セット）。
- **指定ログイン情報（Named Credential）**と**外部ログイン情報**で、Salesforce から外部を呼ぶときの認証情報を安全に管理。
- 双方向 TLS（相互認証）、IP 制限、項目の暗号化（Shield Platform Encryption）。

## 4. エラー処理と信頼性

- **再試行**: 一時的なエラー（タイムアウトなど）は間隔を空けて再送。
- **冪等性**: 同じメッセージが 2 回届いても結果が変わらないようにする（**外部 ID で upsert**）。
- **順序**: 順番が重要なデータは、順序を保証する仕組み（シーケンス番号、単一の処理キュー）を設計。
- **エラーの記録と通知**: 失敗をログオブジェクトや監視ツールに残し、担当者に通知。
- **ミドルウェア**を使うと、変換・再試行・監視を一元化できる。
