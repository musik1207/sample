## この範囲で問われること

- Apex からのコールアウトの実装と制約
- 宣言的な連携（外部サービス、Flow の HTTP コールアウト）
- 非同期処理の選択（Future・Queueable・Batch・Schedule）
- テストとモック

## 1. Salesforce から外部を呼ぶ

| 方法 | 特徴 |
|---|---|
| **Apex コールアウト（HttpRequest）** | 柔軟。指定ログイン情報と組み合わせる |
| **WSDL から Apex クラスを生成** | SOAP サービスの呼び出し |
| **外部サービス（External Services）** | OpenAPI 仕様を登録すると、Flow からノーコードで呼べる |
| **Flow の HTTP コールアウト** | 宣言的に REST API を呼び出す |
| **アウトバウンドメッセージ** | 宣言的に SOAP 通知を送る |

### コールアウトの制約

- **DML の後に同じトランザクションでコールアウトはできない**（未コミットの作業があるとエラー）→ 順番を入れ替えるか、非同期にする。
- **トリガーから同期コールアウトはできない** → `@future(callout=true)` や Queueable を使う。
- リモートサイト設定または**指定ログイン情報**でエンドポイントを登録する。

## 2. 非同期 Apex

| 種類 | 使いどころ |
|---|---|
| **Future** | 単純な非同期処理・コールアウト。プリミティブ型の引数のみ |
| **Queueable** | 複雑な型を渡せる、連鎖（チェーン）できる、ジョブ ID で監視 |
| **Batch Apex** | 大量レコードを分割して処理 |
| **Schedulable** | 決まった時刻に実行 |

## 3. 外部から Salesforce を呼ぶ

- 標準の REST / SOAP / Bulk API で済むなら、まずそれを使う。
- 独自のロジック（複数オブジェクトの一括処理、検証）が必要なら **Apex REST** でエンドポイントを公開する。
- 連携ユーザーと接続アプリケーションでアクセスを管理する。

## 4. テスト

- コールアウトはテストで実際に呼べないため、**HttpCalloutMock**（SOAP は WebServiceMock）で応答を模擬する。
- 正常系だけでなく、**エラー応答・タイムアウト**の処理もテストする。
- 本番リリースには Apex のコードカバレッジ（組織全体で 75% 以上）が必要。
