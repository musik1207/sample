## この範囲で問われること

- 連携の監視と障害対応
- API 使用量と制限の管理
- 連携の変更・バージョン管理

## 1. 監視

- **ログ**: 送受信の結果やエラーをカスタムオブジェクト・イベントログ・ミドルウェアに記録する。
- **イベントモニタリング（Shield）**: API の呼び出しやログインなどを詳しく分析。
- **API の使用状況**: システム概要や REST API の Limits リソースで残量を確認。上限に近づいたら通知。
- **非同期ジョブの監視**: Apex ジョブの画面で失敗を確認。
- **アラート**: 失敗が続いたら担当者に通知し、手動で再処理できるようにする。

## 2. 障害対応

- 外部システムの停止時: **再試行キュー**にためて、復旧後に送る。
- データの不整合: **照合（リコンシリエーション）**の仕組みで定期的に差異を検出する。
- **ランブック（手順書）**を用意し、誰でも同じ手順で対応できるようにする。

## 3. 変更とバージョン

- Salesforce の API は**バージョン**を指定して呼ぶ。古いバージョンは廃止されることがあるため、計画的に更新する。
- 外部システムの仕様変更に備え、連携部分を**疎結合**にしておく（ミドルウェアや共通の連携クラス）。
- 変更は Sandbox で検証してから本番へ。
