## この範囲で問われること

- 現行システムの構成と、各システムの役割の把握
- 連携に影響する制約（プロトコル、認証、ネットワーク、性能）
- 標準・規格（REST/SOAP、OAuth、SAML など）の理解

## 1. 把握すべきこと

| 観点 | 確認すること |
|---|---|
| システムの役割 | どのシステムがどのデータのマスター（正）か |
| 技術 | 提供している API の種類（REST・SOAP・ファイル・DB 直結）、対応する認証方式 |
| 量とタイミング | データ量、更新頻度、リアルタイム性の必要度 |
| ネットワーク | ファイアウォール、社内ネットワーク内か、IP 制限 |
| 既存の連携基盤 | ESB・ETL・MuleSoft などの有無 |
| 制約 | 外部システムの API 上限、メンテナンス時間、セキュリティポリシー |

## 2. 主な標準・プロトコル

- **REST**: 軽量。JSON。モバイルや Web で一般的。
- **SOAP**: WSDL による厳密な型。企業システムで古くから使われる。
- **OAuth 2.0**: API の認可。フロー（Web サーバー、JWT ベアラー、クライアントクレデンシャルなど）を用途で選ぶ。
- **SAML / OpenID Connect**: シングルサインオン（SSO）。
- **ファイル連携**（CSV など）: 大量データの夜間一括処理に使われる。

## 3. 制約が設計を決める

- 外部システムが**社内ネットワーク内**にあり Salesforce から直接届かない → ミドルウェアや中継を検討。
- 外部システムが **SOAP しか提供しない** → Apex の WSDL からのクラス生成や、ミドルウェアでの変換。
- 外部の API に**呼び出し回数の上限**がある → まとめて送る、キャッシュする、非同期にする。
