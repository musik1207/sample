## この範囲で問われること

- 連携パターンの選択
- 同期と非同期
- Salesforce の制限（ガバナ制限、API 上限）の考慮
- データ量とタイミングに応じたツールの選択

## 1. Salesforce の連携パターン

| パターン | 内容 | 例 |
|---|---|---|
| **リモートプロセス呼び出し — 要求と応答** | Salesforce から外部を呼び、**結果を待つ**（同期） | 与信チェックの結果を画面に表示 |
| **リモートプロセス呼び出し — Fire and Forget** | Salesforce から外部に送り、**結果を待たない**（非同期） | 受注を ERP に通知（プラットフォームイベント、アウトバウンドメッセージ） |
| **バッチデータ同期** | 大量データを定期的に同期 | 夜間に商品マスターを取り込む（ETL、Bulk API） |
| **リモート呼び出し** | 外部から Salesforce を呼ぶ | 外部システムがレコードを作成・更新（REST/SOAP API） |
| **UI の更新（データ変更に基づく）** | Salesforce のデータ変更を画面に即時反映 | Streaming / 変更データキャプチャ＋Lightning |
| **データの仮想化** | データをコピーせず参照 | Salesforce Connect の外部オブジェクト |

## 2. 同期か非同期か

- **同期**: 利用者が結果を待つ必要があるとき。**タイムアウト**（Apex コールアウトは最大 120 秒）とエラー時の画面表示を考える。
- **非同期**: 待つ必要がない、量が多い、外部が遅い・止まることがあるとき。**再送の仕組み**と**順序**を考える。

## 3. 制限を考慮する

- **Apex のコールアウト**: 1 トランザクションの回数上限、タイムアウト、トリガーから直接は同期コールアウトできない（`@future(callout=true)` や Queueable を使う）。
- **API 要求の上限**: 24 時間あたりの API 呼び出し数（ライセンス数で決まる）。
- **Bulk API**: 大量データ（数万件以上）の処理に。非同期でバッチに分割される。
- **プラットフォームイベント**: 発行・配信の上限がある。

## 4. ツールの選択（目安）

| 状況 | 選択 |
|---|---|
| 数件〜少量、すぐに反映 | REST API、Composite API |
| 数万〜数百万件 | Bulk API 2.0 |
| Salesforce の変化を外部に伝える | 変更データキャプチャ、プラットフォームイベント |
| 外部データを表示するだけ | Salesforce Connect |
| 多数のシステム、変換・オーケストレーション | MuleSoft などの連携基盤 |
