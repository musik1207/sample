## この範囲で問われること

- 利用者リサーチの手法
- ペルソナとジャーニーマップ
- ワークショップの手法とプロトタイプ
- 利用者のニーズと Salesforce の機能の対応付け

## 1. 利用者リサーチ

| 手法 | 向いている場面 |
|---|---|
| **インタビュー** | 動機や不満の背景を深く知る |
| **観察（シャドーイング）** | 実際の行動と、言葉にされない手間を知る |
| **アンケート** | 多くの人の傾向を数字で知る |
| **既存データの分析** | 利用状況やログから事実を知る |

- **聞くこと**より**観察すること**から本当の課題が見つかることが多い（人は自分の行動を正確に説明できない）。
- 調査結果は**親和図（アフィニティダイアグラム）**でグループ化し、パターンを見つける。

## 2. ペルソナとジャーニーマップ

- **ペルソナ**: 調査に基づく代表的な利用者像（目的・行動・不満）。**架空の理想像ではなく事実に基づく**。
- **カスタマージャーニーマップ**: 顧客がサービスと関わる流れを段階ごとに描き、行動・感情・接点・課題を可視化する。
- **サービスブループリント**: ジャーニーの裏側にある、社内の担当・システム・プロセスまで描く。
- **共感マップ**: 利用者が「言うこと・考えること・すること・感じること」を整理する。

## 3. ワークショップとプロトタイプ

- **アイデア出し**: 量を重視し、批判せずに出す → その後に**優先順位付け**（インパクト × 実現しやすさのマトリックス、投票）。
- **プロトタイプ**: 早く・安く作って試す。紙のスケッチ、画面のモックアップ、Salesforce の Sandbox で設定したもの。
- **忠実度**は目的に合わせる: アイデアの確認なら低忠実度（スケッチ）、使い勝手の確認なら高忠実度。
- プロトタイプは**利用者にテスト**してもらい、フィードバックで改善する。

## 4. ニーズと機能の対応付け

- 利用者のニーズを、Salesforce の**大まかな機能**に対応付ける（例: 「外出先で情報を見たい」→ モバイルアプリ、「問い合わせを自己解決したい」→ Experience Cloud とナレッジ、AI エージェント）。
- この段階では**詳細な設計ではなく、方向性**を示す。詳細はアーキテクトや BA と協力して詰める。
- **ロードマップ**: 価値の高いものから段階的に提供する計画を描く。
