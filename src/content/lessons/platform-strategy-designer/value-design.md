## この範囲で問われること

- 課題の定義（チャレンジステートメント）
- ビジネス目標と利用者のニーズの両立
- 成功指標（KPI）の設定
- 組織の内外の要因（制約・リスク・機会）の考慮

## 1. 戦略デザイナーの考え方

Strategy Designer は、**何を作るか**の前に**なぜ作るのか・誰のためか**を明確にする役割です。

- **ビジネスの価値**（売上・コスト・リスク）と**人間の価値**（利用者の使いやすさ・満足）の**両方**を満たす解決策を目指す。
- デザイン思考の流れ: **共感（理解）→ 問題定義 → アイデア → プロトタイプ → テスト**。行ったり来たりしながら進める。

## 2. チャレンジステートメント（解くべき問い）

- 「**どうすれば（How Might We）** 〜できるか？」の形で、課題を前向きな問いにする。
  - 例: 「どうすれば、営業担当者が移動中でも 5 分で商談の準備ができるようになるか？」
- 良い問いの条件
  - **広すぎない**（「顧客体験を良くする」では漠然としすぎ）
  - **狭すぎない**（「ボタンを追加する」は解決策を決めつけている）
  - **ビジネス目標と利用者の課題の両方**を含む
- 問いは**リサーチの結果に基づく**。思い込みではなく、利用者への調査で得た事実から作る。

## 3. 成功指標

| 種類 | 例 |
|---|---|
| ビジネス指標 | 売上、成約率、コスト削減、解約率 |
| 利用者の指標 | タスク完了時間、満足度、利用率 |
| 先行指標 | 早く変化が見える指標（例: ログイン率、入力率） |
| 遅行指標 | 結果として後から出る指標（例: 年間売上） |

- 指標は**プロジェクトの最初に決め、基準値を測っておく**。
- 遅行指標だけだと効果が分かるまで時間がかかるため、**先行指標を組み合わせる**。

## 4. 内外の要因

- **組織の要因**: 予算、体制、スキル、既存システム、組織文化、変化への準備度。
- **外部の要因**: 市場の動向、競合、規制・法令、技術の変化。
- 要因を踏まえて、**実現可能性（Feasibility）・事業性（Viability）・望ましさ（Desirability）**のバランスをとる。
